# volatile 与编译器优化

## 一句话

编译器会删掉"看起来没用的"代码。加 `volatile` 告诉它："别删，我是故意的。"

## 案例

OLED 通信（I2C）需要微秒级延时。写了一个空循环：

```c
// ❌ 会被优化掉
for (uint8_t i = 0; i < 10; i++);  // 什么都没做 → 编译器：删了！
```

编译器开优化（-O1/-O2）时，发现这个循环"不产生任何效果"，直接删除。

后果：`I2C_Delay()` 变成零延时 → OLED 通信出错 → 花屏、乱码。

## 修法

```c
// ✅ volatile 保护
volatile uint32_t delay = 50;
while (delay--);  // 编译器：这个变量随时可能变，不能优化
```

`volatile` 的含义："这个变量的值可能在任何时刻被外部因素改变，不要假设你知道它的值，老老实实每次重新读。"

## 另一个解：硬件定时器

```c
HAL_Delay(100);  // 用 SysTick 硬件定时，绝对可靠，编译器删不掉
```
