# 串级 PID

> H 题核心控制架构：球位置（外环）+ 摆杆倾角（内环）

## 一、为什么需要两层

### 类比：端一碗水走路

| 你的操作 | 对应的控制环 |
|----------|-------------|
| **手** — 保持碗水平 | **内环** — 舵机保持摆杆姿态 |
| **脚** — 往前走 | **外环** — 球位置控制 |

**手（内环）比脚（外环）快得多**——水还没洒，手已经感觉到了碗的倾斜并调回去了。

---

## 二、单层 vs 串级

### 单层 PID：球偏了 → 舵机

```
车颠簸 → 管子歪 3° → 球开始滚 → 球滚了 1cm → VL53L0X 发现 → PID 算 → 舵机动
                                     ↑
                              等球动了才知道，慢一拍
```

### 串级 PID：两个环协同

```
车颠簸 → 管子歪 3° → MPU6050 0.005秒发现 → 内环立刻压住
                          ↓
                    球甚至还没开始滚，管子已经回正了
```

| | 传感器 | 目标 | 频率 |
|------|--------|------|------|
| **外环** | VL53L0X（看球） | 决定"管子该倾几度" | 50Hz（20ms）|
| **内环** | MPU6050（看管子倾角） | 执行"管子倾到目标角度" | 200Hz（5ms）|

---

## 三、为什么频率不同

**球比管子慢得多：**

```
管子被舵机推 1°：0.005 秒（几乎瞬间）
球滚 1cm：      0.2 秒以上（有惯性）
```

如果外环和内存一样快（5ms 一次）：

```
外环: "球还是偏的？再倾！"
      → 管子越倾越多 → 球终于滚了 → 冲过头 → 振荡
```

外环 20ms 跑一次 = **给球时间滚到位，看清楚了再决定还要不要调。**

```
频率比例 ≈ 响应速度比例。谁快谁跑高频。
```

---

## 四、数据流（H 题 Mode 4）

```
传感器层:
  VL53L0X  → 到钢珠的距离(mm) → 球偏差 = 目标距离 - 实际距离
  MPU6050  → 加速度/角速度    → 管子实际倾角 + 偏航角 + 转弯检测

控制层:
  外环 PID → 输入: 球位置偏差      → 输出: 管子目标倾角
  内环 PID → 输入: 倾角偏差(目标vs实际) → 输出: 舵机 CCR 值

执行层:
  舵机 → 收到 CCR → 连杆拉/推管子 → 管子倾斜 → 球往低处滚
```

---

## 五、MPU6050 的位置

**装车身上，不装管子上。**

理由：
- 偏航角需要 Z 轴始终朝上 → 管子会左右倾斜，Z 轴跟着歪
- 装车身上，Z 轴永远指向天 → 偏航角准

```
管子角度 = 车身倾角（MPU6050 测）+ 舵机命令角度（代码里已知）
```

---

## 六、MPU6050 数据的三重用

| 用途 | 怎么算 |
|------|--------|
| 管子实际倾角 | 车身倾角 + 当前舵机命令角度 |
| 偏航角（一圈判定） | Z 轴角速度 Gz 积分 |
| 转弯前馈（预留） | Z 轴角速度 Gz 直接读 |

**一个传感器，一个位置，三种用途。**

---

## 七、代码结构（多频率共存）

内环和巡线 PID 每 5ms 跑，外环每 4 次循环跑一次（计数法）：

```c
static uint8_t outer_cnt = 0;

while(1) {
    // === 每圈都跑 (200Hz) ===
    巡线 PID + 电机控制;
    内环 PID（舵机）;
    MPU6050 读取;

    // === 每 4 圈跑一次 (50Hz) ===
    outer_cnt++;
    if(outer_cnt >= 4) {
        outer_cnt = 0;
        外环 PID（球位置）;
    }

    // === 每 500ms 跑一次 (2Hz) ===
    if(HAL_GetTick() - oled_timer > 500) {
        刷新 OLED;
    }

    HAL_Delay(5);
}
```

不用多个 Delay——**快的每圈跑，慢的数圈跑。** 和 OLED 刷新用的是同一个技巧。
