# I2C 通信协议

## 一、基本概念

I2C 用**两根线**完成通信：

| 线名 | 全称 | 作用 | 类比 |
|------|------|------|------|
| **SCL** | Serial Clock | 时钟线，ST下发节拍 | 老师敲黑板——告诉你"什么时候听" |
| **SDA** | Serial Data | 数据线，收发轮流用 | 老师说的话本身 |

---

## 二、地址机制

每个 I2C 设备出厂时就有**唯一的地址**：

```
                ┌──────────┐
                │  STM32   │  ← 主机
                └────┬─────┘
                     │
        ═══════════╪═══════════  两根线（SCL + SDA）
                     │
        ┌────────────┼────────────┐
        │            │            │
        │ MPU6050    │ VL53L0X    │
        │ 0x68       │ 0x29       │
        └────────────┴────────────┘
```

**MCU 说话前先喊名字：** "0x29号！把你的数据发过来。" 只有地址匹配的设备会回应，其他设备当没听到。

**SDA 收发轮流用**（半双工）：不像串口 TX 发 RX 收各走各的线，I2C 的 SDA 一根线，MCU 说完 释放总线，传感器再在这根线上回话。

---

## 三、软件 I2C vs 硬件 I2C

| | 软件 I2C | 硬件 I2C |
|------|----------|----------|
| **谁在模拟时序** | CPU 一条一条指令手动翻转 IO | 芯片内部的 I2C 外设自动完成 |
| **代码复杂度** | 手动写延时、等待、ACK 判断 | `HAL_I2C_Master_Transmit()` 一行搞定 |
| **CPU 占用** | 传输期间 CPU 全程卡住 | 硬件自动干活，CPU 解放 |
| **速度** | 慢 | 快（最高 400kHz） |
| **占用引脚** | 随便哪个 IO | 只能用芯片指定的引脚 |

当前项目：OLED 用软件 I2C（PB8/PB9）；新加的 VL53L0X + MPU6050 用硬件 I2C1（PB6/PB7）。

---

## 四、H 题项目的 I2C 分配

```
I2C1 总线：
  PB6 → SCL ─┬─→ VL53L0X (地址 0x29)
  PB7 → SDA ─┤
              └─→ MPU6050 (地址 0x68)

两个设备同一根总线，地址不冲突。
```

---

## 五、基本通信流程

```
1. MCU 发出 START 信号（SCL 高时 SDA 下降沿）
2. MCU 发出 7位设备地址 + 1位读写位（HAL 自动处理）
3. 目标设备回应 ACK（拉低 SDA 1 个时钟）
4. MCU 发出寄存器地址
5. 设备发送寄存器数据
6. MCU 发出 STOP 信号
```

## 六、代码示例：读 VL53L0X 距离

```c
uint8_t buf[2];
HAL_I2C_Mem_Read(
    &hi2c1,                  // 用 I2C1
    0x29 << 1,               // 设备地址 0x29，HAL 要求左移1位 → 0x52
    0x1E,                    // 起始寄存器地址
    I2C_MEMADD_SIZE_8BIT,    // 寄存器地址占 8 位
    buf,                     // 数据存这里
    2,                       // 读 2 字节
    100                      // 超时 100ms
);

// 拼出 16 位距离值
uint16_t distance = (buf[0] << 8) | buf[1];
// buf[0] 高字节左移8位 + buf[1] 低字节
// 如 buf[0]=0x00, buf[1]=0x84 → 0x0084 = 132mm
```

**为什么地址要 `<< 1`？** HAL 要求——I2C 协议最低位用来区分读写（0=写 1=读），HAL 自动填，你给高 7 位。
