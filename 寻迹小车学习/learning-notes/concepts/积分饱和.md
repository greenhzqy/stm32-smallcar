# 积分饱和

## 一句话

水桶太大，还没反应过来就满了，积分失去了"慢慢积累"的意义。

## 直觉

你有一个水桶，每次车偏左就往里加水，偏右就舀水。桶里的水代表"你历史上偏了多少"。

正常情况下，桶应该**慢慢**装满（比如 0.5~1 秒），这样它代表的是"最近这段时间的整体趋势"。

但如果桶太小或者水流太大——100ms 就满了——桶里的水量就不能反映趋势了。它变成了一个瞬间饱和的开关：要么满、要么空。

## 我遇到的问题

```c
Ki = 0.5           // 积分系数太大
sum_error += error; // 每 5ms 累加一次

// 典型偏差 ±1，每秒 200 次累加
// 1 秒内：sum_error = 200 × Ki = 100
// 但上限只有 ±10，100ms 就饱和了！
```

积分项占 PID 输出的 33%（正常应该 5~10%），抢了 [[PID三个参数|Kp]] 的方向盘。

## 解法

两招并用：

| 招数 | 改前 | 改后 |
|------|:--:|:--:|
| 降 Ki | 0.5 | **0.15** |
| 缩上限 | ±10 | **±3** |

效果：积分从饱和时间 100ms → 300ms，从占输出 33% → 5%。

## 另一招：丢线时冻结积分

丢线（全白）时继续累加积分 = 火上浇油。因为丢线时 error 被冻结在 `last_error`，积分会基于同一个 error 不断累加。

```c
// 丢线时不累加积分
if(!line_lost) {
    sum_error += error;
}
```
